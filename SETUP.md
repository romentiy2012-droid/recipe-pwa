# Подключение импорта, Google Drive и Dropbox

Обычные рецепты, меню, теги, заметки, покупки и PDF уже работают без регистрации. Сервер импорта и OAuth-клиенты нужно один раз развернуть/зарегистрировать у их провайдеров. Подключение Google Drive к ChatGPT не авторизует отдельное веб-приложение.

## 1. Импорт по ссылке

В репозитории готов обработчик Cloudflare Workers: `importer/worker.mjs`, конфигурация — `importer/wrangler.toml`. Он загружает HTML и фотографии с явно разрешённых сайтов, проверяет адрес каждого перенаправления и ограничивает размер ответа. Клиент разбирает Schema.org Recipe (JSON-LD, включая @graph/HowToSection, или microdata) и открывает редактор для проверки.

1. Войди в свой аккаунт Cloudflare. На компьютере с Node.js выполни из каталога проекта:
   ```bash
   npx wrangler login
   npx wrangler deploy --config importer/wrangler.toml
   ```
2. Wrangler покажет адрес вида `https://recipes98-import.<твой-поддомен>.workers.dev`.
3. В приложении открой **Облако → Настройка подключений**, вставь этот адрес в поле обработчика и нажми **Сохранить настройки**.
4. Открой **Из интернета**, вставь ссылку, нажми **Извлечь рецепт**, выбери найденный рецепт, проверь и сохрани.

`ALLOWED_ORIGIN` должен быть `https://romentiy2012-droid.github.io` (без пути `/recipe-pwa/`). `ALLOWED_HOSTS` содержит разрешённые домены; поддомены этих доменов разрешены. Чтобы подключить другой кулинарный сайт или его отдельный CDN фотографий, добавь точный доверенный домен и повтори deploy. Обработчик намеренно не является открытым прокси для любых адресов. Не добавляй локальные/служебные домены.

Некоторые сайты требуют авторизации, отдают защитную страницу, динамически формируют рецепт или не публикуют разметку. Универсального импорта «любого рецепта с любого сайта» нет. Для таких страниц есть вставка исходного HTML или текста; исходная ссылка сохраняется. Приложение не обходит вход, платный доступ и защиту сайта. Поиск в интернете открывает Google в отдельной вкладке, после чего ссылка импортируется в книгу.

### Альтернатива: Vercel

В `importer/api/import.mjs` и `importer/vercel.json` готов адаптер того же обработчика для Vercel. Создай отдельный Vercel Project из этого репозитория, выбери Root Directory `importer`, framework Other, без команды сборки и без output directory. Маршруты `/page` и `/image` ведут в Node Function. `ALLOWED_ORIGIN` по умолчанию задан для этой книги; при необходимости задай переменные `ALLOWED_ORIGIN` и `ALLOWED_HOSTS`. Полученный адрес проекта вставь в поле обработчика в приложении.

Подключение Vercel к ChatGPT позволяет продолжить развёртывание через доступные возможности этого подключения после авторизации. Сам факт наличия кода и предложения подключиться не означает, что сервер уже опубликован.

## 2. Google Drive

1. В [Google Cloud Console](https://console.cloud.google.com/) создай проект или выбери свой.
2. Включи **Google Drive API**.
3. Настрой экран OAuth consent. Для личной проверки в режиме Testing добавь свой Google-аккаунт в Test users.
4. Создай OAuth Client ID типа **Web application**.
5. В **Authorized JavaScript origins** добавь `https://romentiy2012-droid.github.io` (без пути). Для локальной проверки можно отдельно добавить `http://localhost:8000`.
6. Скопируй публичный **Client ID**, заканчивающийся на `.apps.googleusercontent.com`, в настройки приложения. Client Secret и API key для этой реализации не нужны.
7. Нажми **Войти в Google Drive**, выбери аккаунт и разреши доступ к данным этого приложения. Затем нажми **Синхронизировать Drive**.

Используется только scope `https://www.googleapis.com/auth/drive.appdata` — скрытая папка данных данного OAuth-приложения, а не доступ ко всем файлам Диска. На всех устройствах используй один Client ID и один Google-аккаунт. Короткоживущий токен хранится только в памяти страницы; после перезапуска или истечения срока снова нажми «Войти».

Документация: [Google token model](https://developers.google.com/identity/oauth2/web/guides/use-token-model), [Drive appDataFolder](https://developers.google.com/workspace/drive/api/guides/appdata).

## 3. Dropbox

1. В [Dropbox App Console](https://www.dropbox.com/developers/apps) создай **Scoped access** приложение типа **App folder**.
2. Разреши scopes `files.metadata.read`, `files.content.read`, `files.content.write` и сохрани настройки Permissions.
3. В OAuth 2 Redirect URIs добавь точный адрес `https://romentiy2012-droid.github.io/recipe-pwa/` со слешем на конце.
4. Публичный **App key** вставь в настройки приложения. App secret не нужен.
5. Нажми **Войти в Dropbox**. После разрешения доступа браузер вернётся в приложение. Нажми **Синхронизировать Dropbox**.

Используется Authorization Code + PKCE (S256), проверка state и срока входа. Короткоживущий токен хранится в sessionStorage текущего окна; он не записывается в экспорт, репозиторий или долговременное локальное хранилище. Приложение работает только в своей папке Dropbox. На других устройствах укажи тот же App key и войди в тот же аккаунт.

Документация: [Dropbox OAuth guide](https://developers.dropbox.com/oauth-guide).

## 4. Как синхронизировать устройства

На первом устройстве войди и нажми **Синхронизировать**. Затем сделай то же на втором. После новых изменений повтори синхронизацию на устройстве, где были изменения, и на устройстве-получателе. Это явная синхронизация по кнопке, без постоянной фоновой передачи и без обещания фоновой работы на iOS.

Каждое устройство записывает свой файл-снимок; чужие файлы устройств не перезаписываются. Записи рецептов имеют UUID, ревизии и предков. Последовательные изменения объединяются; одновременные независимые версии сохраняются отдельной копией с названием «(конфликт)». В корзине рецепты синхронизируются как обычно. Окончательное удаление оставляет отметку удаления, чтобы другое устройство не вернуло рецепт автоматически. При необходимости сохрани нужную конфликтную копию под новым рецептом.

Меню объединяется по идентификаторам записей и времени изменения, включая отметки удалённых блюд. Список покупок выбирается целиком по времени последнего изменения, поэтому перед одновременным редактированием покупок на двух устройствах синхронизируй их. Для разрешения порядка изменений часы устройств должны быть настроены правильно. Старые ревизии (более 100 изменений) могут потребовать ручного разбора конфликтной копии.

Перед применением синхронизации сохраняется одна локальная копия исходных данных; кнопка восстановления находится в «Облако». Она не откатывает облачные файлы автоматически. Настройки OAuth, вход и черновик между устройствами не переносятся. Не более 30 файлов устройств на одно подключение. Книга до 100 МБ; используемые ограничения провайдера также применяются.

Если аккаунт Cloudflare или OAuth-клиенты пока не настроены, интерфейс прямо сообщает об этом. Реальные входы нельзя проверить транспортными тестами: авторизацию должен выполнить владелец соответствующего аккаунта.

## 5. Быстрый приём ссылки и iPhone

В manifest добавлен Web Share Target для поддерживающих его браузеров. При выборе установленного приложения в меню «Поделиться» ссылка попадёт в экран импорта. Поддержка этого способа зависит от ОС и браузера; он не обещается на iPhone.

Альтернатива через «Команды» iPhone: создай команду, которая принимает URL из меню «Поделиться», кодирует его для URL и открывает:

`https://romentiy2012-droid.github.io/recipe-pwa/?recipe_url=<закодированная-ссылка>`

Включи «На странице экспорта». Открытие ссылки передаёт её в импорт; извлечение и сохранение требуют проверки рецепта. Обычный переход по ссылке может открываться в Safari, отдельно от установленной PWA; для одной библиотеки используй один и тот же способ запуска приложения.

## 6. PDF и проверки

PDF формируется прямо на устройстве с кириллическим шрифтом и доступен офлайн после загрузки ресурсов приложения. Экспортируется один рецепт или вся активная книга, включая фотографии, заметки и источник. Сторонние компоненты и лицензии находятся в `vendor/`: jsPDF 4.2.1 и подмножество DejaVu Sans. Платных ограничений, рекламы и водяных знаков нет.

```bash
npm ci
npm test
npx playwright install chromium
npm run test:browser
npm run test:book
```

Браузерные тесты запускают локальный сервер на порту 8000. Входы в облака и сетевые ответы проверяются имитациями HTTP; реальные аккаунты и развёрнутый Worker нужно проверить отдельно. Тесты не обращаются к пользовательской базе.
