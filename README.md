# 🍳 Мои рецепты 98 — PWA

Прогрессивное веб-приложение для хранения рецептов с фотографиями и офлайн-доступом. Интерфейс в стиле Windows 98.

## ✨ Возможности
- Рецепты с фото (камера или галерея, автосжатие), ингредиентами и шагами
- Поиск по названию, ингредиентам, описанию
- Свои категории, избранное
- Экспорт и импорт всех рецептов в JSON (меню «Файл» или «Пуск → Настройки»)
- Защита от потери данных: при закрытии формы с изменениями спрашивает, сохранить ли
- «Пуск → Завершение работы…» с запросом на сохранение
- Работает офлайн, устанавливается на телефон

## 🚀 Локальный запуск
```bash
python3 -m http.server 8000
```
Открой http://localhost:8000

## 🌐 Деплой на GitHub Pages
1. Залей проект в репозиторий
2. Settings → Pages → Source: main, / (root)
3. Открой https://username.github.io/repo-name/

## 💾 Данные
Всё хранится локально в IndexedDB браузера. Делай экспорт в JSON время от времени — браузеры (особенно iOS Safari) могут чистить локальные данные.

## 🔄 Обновления
Service worker работает по схеме network-first: при наличии сети всегда грузятся свежие файлы. При изменении списка файлов в `sw.js` поднимай `CACHE_NAME`.

## 🍽️ Версия 4 — готовка и сохранность данных
- **Готовлю** в карточке рецепта: крупный текущий шаг, кнопки «Назад / Далее», отметки продуктов. Каждая непустая строка исходного текста считается шагом.
- **Порции:** в редакторе укажи исходное число порций и продукты в отдельных полях «название / количество / единица». При просмотре измени порции: количества пересчитаются, исходный рецепт останется прежним. Принимаются десятичные числа с точкой или запятой и дроби `1/2`, `1 1/2`. Пустое количество не масштабируется.
- **Старые рецепты** сохраняются. Однозначные строки `Мясо — 500 г` разбираются при открытии, остальные остаются целиком в названии продукта. Для старого рецепта исходные порции нужно задать в редакторе; приложение их не угадывает.
- **Покупки:** добавляй продукты из карточки или выбери несколько блюд на экране «Покупки». Одинаковые названия без учёта регистра объединяются; кг переводятся в г, л — в мл. Ложки, стаканы и другие несовместимые единицы остаются отдельно. Отметки «куплено» сохраняются; новая покупка не помечается купленной автоматически.
- **Черновик:** один текущий несохранённый рецепт, включая фото, автоматически записывается в IndexedDB через 300 мс после ввода и при уходе приложения в фон. После перезапуска появится «Восстановить». Выбор «Нет» в диалоге сохранения удаляет черновик. Мгновенное принудительное завершение до записи последних изменений не гарантирует их сохранение.
- **Корзина:** обычное и массовое удаление переносят рецепты в корзину. Восстановление сохраняет фото и избранное; удаление навсегда требует отдельного подтверждения. Автоматической очистки корзины нет.
- **Поделиться:** системное меню телефона, копирование в буфер или текст для ручного копирования, если эти возможности недоступны. Включает выбранные порции и полный текст рецепта.
- **Резервная копия:** кнопка на главном экране показывает дату подготовки последнего экспорта; напоминание внутри приложения появляется, если копии нет или прошло больше 7 дней. Это не системное push-уведомление. Сохрани скачанный JSON в «Файлы» или облако: приложение не может проверить завершение сохранения.

Формат экспорта v2 сохраняет структурированные ингредиенты, порции, фото, корзину и покупки. Импорт принимает v1 и v2, пропускает уже имеющиеся рецепты (включая корзину). Покупки из копии восстанавливаются только если текущий список пуст. Черновик в экспорт не входит. Восстановление копии добавляет рецепты, а не заменяет текущую базу.

Обновление базы с версии 2 до 3 только добавляет хранилище настроек; рецепты и категории не удаляются. Приложение остаётся статическим: сервер и аккаунт для работы не нужны. Для обновления установленной PWA закрой и заново открой её с интернетом.

## Проверки
```bash
npm install
npm test
npx playwright install chromium
npm run test:browser
```
Браузерная проверка сама запускает локальный сервер на порту 8000. Для WebKit: `npx playwright install webkit`, затем `BROWSER=webkit npm run test:browser`. Проверки запускаются в изолированной тестовой базе; пользовательские рецепты не затрагиваются.

## 📚 Версия 5 — кулинарная книга и меню
- Меню по дням и приёмам пищи, переход между неделями, список покупок из меню с учётом порций.
- «Холодильник»: подбор рецептов из своей книги по перечисленным продуктам с показом недостающего.
- Теги, фильтр по тегу, сортировка, личные заметки, исходная ссылка и связи между рецептами.
- Импорт Schema.org Recipe из HTML/по ссылке с проверкой в редакторе; при блокировке сайта — ручная вставка текста. Поиск в интернете открывает поисковик отдельно.
- Настоящий PDF одного рецепта или всей активной книги: кириллица, фото, заметки и источник. jsPDF и шрифт включены локально, экспорт работает офлайн.
- Клиенты Google Drive (appDataFolder) и Dropbox (App folder, PKCE). Явная синхронизация по кнопке, отдельные файлы устройств, сохранение конфликтных копий рецептов и локальной копии до синхронизации.
- Формат JSON v3 включает UUID/ревизии, теги, заметки, связи, меню и отметки окончательного удаления. Импорт v1/v2 сохранён.
- Web Share Target для поддерживающих браузеров и приём ссылки через `?recipe_url=...`.

**Первое подключение:** облака требуют OAuth-регистрации и входа владельца; импорт с сайтов, блокирующих CORS, требует развёртывания готового Worker. Пока это не настроено, интерфейс сообщает о необходимости настройки. Публичные значения можно задать в `config.js` для всей установки или в настройках конкретного устройства. Пароли и client secret не нужны. Подробные шаги и реальные ограничения — в [SETUP.md](SETUP.md).

Резервный JSON сохраняет данные; токены, настройки подключения и черновик в него не входят. Интернет-импорт не гарантируется для страниц без разметки или с защитой. На iPhone Web Share Target не обещается; используйте импорт ссылки или «Команды» по инструкции.
